## HOOK-01 — Daily morning training-day push

**Lens:** Retention (primary).
**Behavioural principle:** Fogg, B = MAP. Motivation and ability are present; the Prompt is missing. The target user has a day job and won't open speculatively.
**Tier:** PAID. (Free users continue to receive only the weekly report push, which keeps push as a clear paid-feature signal.)
**Strava-resilience:** Strava-independent. Source is the plan + voice line library — no run data required.

**Scope**

- Daily push at user-local 06:30 (configurable in Me later — initial cut: fixed time + per-user timezone from `user_settings.timezone`).
- Content drawn from `getSessionVoiceLine(sessionType, isQualityDay)` in `DashboardClient.tsx:1979` (extract to `lib/coaching/voiceLines.ts` as part of this work — it's currently inline and not testable).
- Rest day template: *"Today: rest. Do nothing. It helps."*
- Title format: `"Today: easy 45m."` (concrete, not "Time to train").
- Body: one voice line, no emoji.
- Skip the push when no plan exists, or when the user has the Today screen open within the last 30 minutes (avoid double-prompting).
- Add `daily_push_enabled` boolean to `user_settings` defaulting to `true` for paid/trial users; settings row in Me to opt out.

**Files**

- `lib/coaching/voiceLines.ts` (new — extract from DashboardClient).
- `app/api/push/send-daily/route.ts` (new — cron endpoint).
- `vercel.json` — add daily cron at `0 6 * * *` UTC fanned out per-timezone (or run hourly and filter by local hour — cheaper for a small user base).
- `app/dashboard/DashboardClient.tsx` MeScreen → add `daily_push_enabled` toggle row.
- Supabase migration: `daily_push_enabled BOOLEAN DEFAULT true`.

**Acceptance**

- Paid/trial user with a plan and `daily_push_enabled=true` receives one push on each training day, no later than 07:30 local.
- Push payload exercises `getSessionVoiceLine` for the right session type.
- Free user (no active trial, no subscription) receives no daily push.
- User who opens Today between 06:00 and 06:30 receives no push.
- Cron runs in production against APNs (TestFlight build with `APNS_PRODUCTION=1`) — verified by sending one test push and observing delivery.
- Push title uses `BRAND.push.dailyTraining` (new key in `lib/brand.ts`).

**Out of scope**

- AI-generated daily push body (deferred — voice lines are good enough and avoid Haiku spend on every push).
- Configurable push time. (Locked to 06:30 local at v1.)
- Push for cross-train or strength days (treat as rest day at v1).

## KIT-TASTE-01 — One free Kit insight per week, sourced from manual RPE

**Lens:** Conversion (primary). Retention (secondary — free users come back to log RPE).
**Behavioural principle:** Cialdini reciprocity + Eyal variable reward. Free users *taste* the paid product, calibrating value against their own experience.
**Tier:** FREE (the insight itself), but uses paid infra (Haiku call).
**Strava-resilience:** **Strava-independent by design.** This is the entire point of the item — give free users coaching value from manual RPE alone, no Strava required.

**Scope**

- New API route `app/api/coaching/weekly-free-insight/route.ts` (called by the existing Sunday push cron or on Coach tab load — pick: pull-on-view, not push, to avoid cron complexity at v1).
- Generates one short Kit insight per week per free user, sourced from:
  - Last 7 days of `session_completions` rows (manual completions + RPE + fatigue tag).
  - No `run_analysis`, no streams, no Strava. The whole prompt is RPE + session type + fatigue tag + planned vs actual completion ratio.
- Output cached in a new `free_insights` table keyed by `(user_id, week_start_date)`. One generation per user per week — re-renders read from cache.
- Surfaced on the **Coach tab for free users**, replacing the current fully-dimmed `CoachTeaser`. Locked stats stay locked; the insight card unlocks above them.
- Insight card carries `<CoachByline />` + AIMark (it's real model output).
- Required: at least 2 logged completions with RPE in the last 7 days, else show the existing "log a session to unlock your weekly Kit note" empty state.

**Files**

- `lib/coaching/prompts/freeInsight.ts` (new — Haiku prompt).
- `app/api/coaching/weekly-free-insight/route.ts` (new — auth + cache + Haiku call).
- Supabase migration: `free_insights` table — `(user_id, week_start_date, headline, body, created_at)`.
- `app/dashboard/DashboardClient.tsx` — CoachTeaser rewrite to render the insight card when available.
- `lib/plan/featureGates.ts` — verify free users can call this route (it's an exception to the general "free → no Haiku" rule; gate the API by `tier !== 'free'` OR (`tier === 'free'` AND ≥2 RPE logs in last 7d AND no insight this week)).

**Acceptance**

- Free user with 2+ RPE logs in last 7 days sees a Kit note card on Coach tab.
- Insight card has CoachByline + AIMark.
- Re-loading Coach tab does not regenerate (reads cache).
- New week (Mon 00:00 local) → next visit regenerates.
- Free user with 0 RPE logs sees the existing upgrade-cued empty state.
- Paid user sees no behaviour change — the full weekly report path is unchanged.
- Insight is silenced when reframe risk gate would fire (re-use `reframeRiskGate.ts` decision — if any overload signal is active, render rule-engine amber warning instead, no AIMark).

**Out of scope**

- Push delivery of the free insight — surface is pull-on-view only at v1.
- Insight history view — only the latest week's insight is visible.

## SHARE-01 — Shareable weekly zone-discipline card

**Lens:** Referral (primary). Retention (secondary — share moment is also a retention moment).
**Behavioural principle:** Sharp distinctive assets + Cialdini social proof. The card carries `BRAND.name` + the verdict line, designed for Strava feed and Instagram story.
**Tier:** PAID (paid users get a card with their numbers; free users see a blurred preview + upgrade CTA on the Coach tab). Day-one acceptable to ship PAID-only and add the free preview in a follow-up.
**Strava-resilience:** **Strava-independent.** % in zone is sourced from `run_analysis.zones` already, which writes from any source. When Strava is the source the data is denser, but card generation works on HealthKit alone.

**Scope**

- New route `app/api/og/weekly-zone-card/route.tsx` using `next/og` — server-renders a 1080×1920 PNG (Instagram story) or 1200×630 (Twitter/social).
- Inputs: `user_id`, `week_start`. Pulls last weekly_report row + zone-discipline % + `auth.users.created_at`.
- Layout: top — `BRAND.name` wordmark. Middle — the zone-discipline %, large. Below — `getVerdictVoice()` line. Bottom — `BRAND.voiceAnchor` ("Hold the zone.") as small caption. Beneath that, smaller still, the **tenure caption** — `"Holding the zone since {Mmm YYYY}"` sourced from `auth.users.created_at` formatted as month + year only (no day, no time).
- Use Warm Slate hex from `BRAND.og.*` (intentional `next/og` exception — already documented).
- Add "Share this week" affordance on Coach tab (paid) and at the bottom of the weekly report — single button that opens native share sheet with the PNG.
- iOS: use `@capacitor/share` to invoke iOS share sheet. Web: download fallback.

**Tenure caption — explicit rules (rejected forms):**

- Never use the word "member" or "subscriber" — those import a SaaS-club register the brand rejects.
- Never use `created_at` to compute milestones (anniversaries, "1 year of zones") and never push notify on tenure-derived events.
- The tenure caption appears **only on the shareable card** — never in the app, never on Me, never on the founder note. The screenshot is the only place tenure does useful work.
- Format: `"Holding the zone since Mar 2026"` — three-letter month, four-digit year. No "Since:" label. No day. No emoji.
- If `created_at` is within the current calendar month (new account), suppress the line entirely. A "Holding the zone since May 2026" line generated *in May 2026* reads as hollow — the user has been at it for days, not months.

**Files**

- `app/api/og/weekly-zone-card/route.tsx` (new).
- `app/dashboard/DashboardClient.tsx` — CoachScreen → Share button.
- `package.json` — add `@capacitor/share`.
- `capacitor.config.ts` — none needed; Share plugin is JS-only on iOS via the system sheet.

**Acceptance**

- Paid user with a weekly report can tap "Share" → iOS share sheet opens with PNG.
- PNG renders correctly at 1080×1920 with the user's zone-discipline % and verdict line.
- PNG carries `BRAND.name` wordmark + voice anchor — designed for screenshot recognition.
- PNG carries the tenure caption *"Holding the zone since {Mmm YYYY}"* when `auth.users.created_at` is before the current calendar month; suppresses the line for accounts created this month.
- Tenure caption rendered in the smallest typography tier on the card — visible to a viewer studying the screenshot, invisible to a viewer glancing past it.
- No `member`, `subscriber`, `anniversary`, or milestone string appears anywhere in the codebase as a result of this work — verified by grep before merge.
- Card design reviewed against `frontend-design` skill before merge.
- Free user sees a "Share your week" upsell card on Coach tab pointing to UpgradeScreen.

**Out of scope**

- Carousel of multiple weeks. v1 = current week only.
- Custom card backgrounds / themes.
- Auto-push on Sunday — manual share affordance only at v1.
- Tenure surfaces anywhere except the shareable card. (`member-since` style badges, Me-screen rows, founder-note captions, anniversary pushes — all explicitly rejected.)

## LEDGER-01 — "Weeks within the lines" discipline ledger

**Lens:** Retention.
**Behavioural principle:** Eyal investment + Sutherland reframe. The user builds a number that represents *restraint*, not volume.
**Tier:** FREE (the count is everyone's), but the number gets larger when paid features are active (run_analysis-driven % in zone) — natural upgrade pull.
**Strava-resilience:** **Strava-independent.** Free-tier definition uses manual RPE-derived discipline (no Heavy/Wrecked in the week, no skipped quality, ≥4 completed planned sessions). Paid-tier definition uses `run_analysis.zones` for true % in zone. Both paths produce a number; the paid path is more accurate.

**Scope**

- New module `lib/coaching/disciplineLedger.ts`:
  - `computeLedgerForUser(userId, asOfDate) → { weeksWithinLines: number, currentWeekStatus: 'on_track' | 'broken' | 'pending' }`
  - Definition of "within the lines":
    - Free: ≥75% of planned sessions completed AND no `fatigue_tag IN ('Heavy','Wrecked')` AND no skipped quality session.
    - Paid: free criteria + median zone discipline ≥75% across `run_analysis.zones` for the week.
  - Computed lazily on Me-screen open (no cron, no table).
- New surface on **Me screen**: subtle row titled *"Weeks within the lines"* with the number and a quiet caption *"Hold the zone."*
- **No streak mechanics.** No flames. No emojis. No "Don't break your streak!" copy. No broken-streak panic.
- If the user breaks a week, the count resets to 0 silently. No notification. No coaching push. The number going back to 0 is the only feedback.

**Files**

- `lib/coaching/disciplineLedger.ts` (new).
- `app/dashboard/DashboardClient.tsx` — MeScreen new row.
- Tests: `disciplineLedger.test.ts` covering free + paid definitions, single-week reset, multi-week accumulation, partial-week (`currentWeekStatus = 'pending'`).

**Acceptance**

- Free user with 4 weeks of compliant completions sees `Weeks within the lines: 4`.
- Heavy/Wrecked tag in a week resets to 0.
- Paid user gets the more demanding paid definition.
- No surface anywhere uses streak language. No emojis. No urgency.
- Verified against the brand voice rule: *"motivational"* is banned.

**Out of scope**

- All-time max ledger.
- Multi-user leaderboards (would violate the brand).
- Push on ledger milestones (would violate the "no urgency" rule).
