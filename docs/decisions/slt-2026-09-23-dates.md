# SLT — dates: build the owner, don't build the preference (2026-09-23)

**Item:** 9 date formats, 22 hand-written sites, no owner, one raw ISO.
**Founder's ask:** *"standardise everywhere, ideally follow the format of the logged-in user preference."*
**Tier:** FREE (infra). **Outcome:** `DATE-OWNER-01` shipped. **The preference was NOT built.**

## The measurement that changed the question

| | |
|---|---|
| Distinct formats | **9**, across **22** sites, **no owner** |
| Ambiguous (all-numeric, `07/12` style) | 🟢 **ZERO** — every format names its month |
| Raw ISO shown to a runner | **1** — `starts 2026-12-07`, `GeneratePlanScreen:1408` |
| Date/locale preference in `user_settings` | 🔴 **None exists.** Only `preferred_units`, `preferred_metric` |
| Launch market | iOS, **US/UK/anglosphere**, live since 2026-06-15 |

**So this was never a localisation problem.** Nobody misreads `24 Apr 2027`. It was an
*inconsistency* problem plus one defect.

## The seats

- **Sutherland** — *"The rational problem is 'our dates aren't localised.' The real one is that the
  app looks **assembled rather than designed** when one screen says `24 Apr 2027`, another
  `Mon 16 Nov`, and a third `2026-12-07`. Fix the real one. A preference toggle solves the rational
  problem and nobody will ever touch it."*
- **Fried** — *"A new setting is permanent surface area. We'd be adding a preference, a migration, a
  Me-screen row and a branch in every date call — to change **word order** for a population that can
  already read the date. **No.** Build the owner, not the setting."*
- **Wood** — no behaviour changes either way. **The raw ISO is the only thing that would make a
  runner pause**, and pausing on a date is friction on the screen where they commit to a plan.
- **Zhuo** — ADR-015 already owns *"every time/distance/metric string."* Dates were simply never
  brought under it. **Finishing an existing decision, not making a new one.**
- **Hutchinson** — no objection.

## Ruling

**BUILD THE OWNER, DON'T BUILD THE PREFERENCE.**

1. `lib/format.ts → formatDate(date, style)` — 6 named styles replacing 9 ad-hoc option sets.
2. Fix the raw ISO. A defect regardless of anything else.
3. **No new preference, no migration, no Me-screen row.**

⚠️ **THE FOUNDER ASKED FOR THE PREFERENCE AND WAS TOLD PLAINLY WE WERE BUILDING THE OPPOSITE**, with
the counter-argument stated: if he wants US runners to read `Apr 24, 2027` that is a legitimate
call and it needs the setting — but it should be **a decision about market, not tidiness**, and
today nothing is misread.

## 🔻 Recall trigger

Re-open **only** on: shipping outside the anglosphere, **or** a runner actually asking. Absent one
of those, **do not re-propose the date preference** — it has been measured and answered.

## What this does not settle

`'en-GB'` is now hardcoded in **one** place instead of 22. That is the point: the moment a locale
decision is actually made, it is made there, once.
