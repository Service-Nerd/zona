Plan screen · UX audit

The Plan screen has no voice.

It shows you the data — weeks, sessions, distance, completion — and it shows it cleanly. But it doesn't frame the data. Every other screen in the app has Zonna's voice somewhere on it (Today's hero, Session detail's "Why this session", Coach's Kit byline). Plan is the one place users come to understand the arc — and it's silent. That's the headline gap. The rest is consistency drift from Phase 3.

Working well

What's right

Five things the Plan screen already does well — keep them.

Keep

PlanArc visualization

The horizontal week-bars are the Plan screen's best moment. Phase 2 redesign delivered this. Race week in --s-race is a thoughtful touch.

Keep

Move / swap interaction

Tap-to-pick, tap-to-place. Two-step. No drag. Honest about what's about to happen. Better than Runna's drag-reorder, better than Planzy's modal.

Keep

Past weeks collapsed by default

Respects "calm guidance, not noise". User opts in to seeing history. Improve: show them as a compressed strip when expanded, not a full list.

Keep

Information hierarchy

Title → race → arc → context → weeks. Logical flow. Race name placement reads as the goal you're training towards. Don't reshuffle this.

Keep

Skeleton loading state

Three height-stepped skeletons while overrides load. Right pattern per ui-patterns.md §15. Tiny fix: uses --border-col instead of --bg-soft.

Issues

What's broken

Ranked by impact on the experience, not by complexity to fix.

Impact: high

No brand voice anywhere

Plan is the "arc" screen — where users come to understand where they are. It needs a one-line situating statement. PlanCoachingCard already exists in the codebase (line 5320) but it's only used on the Coach screen.

Impact: high

Current week visually weak

Past weeks: opacity 0.65. Current week: same opacity as future weeks + a 3px moss border. The current week should be visually dominant, not subtly differentiated. Hierarchy is wrong.

Impact: medium

Token drift across the whole file

PlanCalendar.tsx still uses System B alias names: --card-bg, --border-col, --text-muted, --accent, --teal-soft, --teal-mid. Aliases bridge it (it renders correctly) but the file is one of five never migrated post-Phase-3.

Impact: medium

Same fact stated 3 times

"Wk 8 of 16" appears in PlanArc top-right. "Build · 3/5 done · 42km target" appears in the week summary line. "W8 · Apr 14–20" appears in every WeekCard header. Each adds slightly different info but the redundancy reads as noise.

Impact: medium

Week-level metric is underweight

42 / 56km renders at 18px. Per ui-patterns.md, the metric pair pattern wants a bold value (44px on hero, 28px+ on cards) over a small unit label. This is the headline week stat — it should own real estate.

Impact: medium

Done vs skipped reads identically

Both states use opacity reduction + an icon at the right. Per SessionCard spec, done = moss check circle, skipped = dashed border + danger strikethrough. Scanning the plan, you should see at a glance what you did vs missed.

Impact: medium

Race week invisible in calendar

PlanArc marks race week in --s-race. PlanCalendar renders it identically to every other week. The most important date on the plan should be visually distinct in both views.

Impact: low

Horizontal padding off-spec

0 12px on the calendar container. Canonical is 0 16px. Same issue called out for Me/Strava in the cross-screen consistency table — add Plan to the list.

Impact: low

Move-mode copy is compound

"tap an empty day to move, or another session to swap" — two clauses, lowercase, mid-card. Brand voice: one sentence. Suggested: "Tap where you want it."

Ship order

Recommendations

Three releases, each shippable independently. SLC at each step.

  1. Pass 1 — Add the voice. S · ~1 day Wire PlanCoachingCard (or a Plan-screen-specific variant of it) into the Plan screen above the calendar. Same rule-engine derivation, no AI. Same component pattern as TodayScreen's coach block. This is the highest-leverage, lowest-risk change — closes the brand-voice gap immediately.
  2. Pass 2 — Token migration + visual hierarchy. M · ~2 days Bring PlanCalendar.tsx onto Warm Slate (mechanical, ~50 LOC of find-and-replace). Same pass: bump the current-week metric pair to 36px, fix the past-week opacity, add the section headers ("Now" / "Next" / "Later"), fix the move-mode copy, race-week --s-race accent. Adds noticeable polish — costs nothing structural.
  3. Pass 3 — Week strip for distant weeks. M · ~2 days New WeekStripCard component using the canonical week strip pattern (ui-patterns.md §3). Past weeks AND weeks ≥3 ahead compress to it; current + next stay as full day lists. Tap-to-expand if the user wants detail on a specific week. Structural change — needs careful testing of the move/swap interaction (does it still work when the source week is compressed?). Defer if the move/swap UX would suffer.
